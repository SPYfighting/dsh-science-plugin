# 路线 B 技术可行性与低缺陷设计调研

日期：2026-11-13  
基线：`@deepseek-ai/dsh@0.2.2-rc.1`；DSH 官方仓库固定提交 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`；DSH Science `0.14.0`。

## 结论

路线 B 可行，但应采用“双层投影”，不能把 DSH Science 项目文件硬塞进原生 session projection：

1. **[事实] 原生会话投影**只折叠已提交的 session event；`init/apply` 是纯同步函数，客户端 `useProjection` 只接收 Host 已算好的整值。因此它适合 Goal、Plan、Agent Team、Action Cards 以及 DSH Science 工具/命令的会话回执，不适合异步读取项目目录或数据库。[projection 类型](../../../../test-env/node_modules/@deepseek-ai/dsh-session-projection/lib/types/index.d.ts#L1-L15) [定义与纯函数约束](../../../../test-env/node_modules/@deepseek-ai/dsh-session-projection/lib/types/index.d.ts#L55-L111) [客户端整值存储](../../../../test-env/node_modules/@deepseek-ai/dsh-api-session-controller/lib/types/client/sessions/projection-store.d.ts#L1-L13)
2. **[推断/推荐] 项目状态**应由 DSH Science 自有的、按 `projectId + rootSessionId` 隔离的持久化存储维护，并通过带 `revision` 的 Remote `snapshot/change/reset` 流投影到卡片、composer 上下文条和右栏。卡片是读模型和控制柄，不是第二真源。
3. **[事实+实测] 外部插件没有受支持的自定义 durable event 注册面。**`appendPluginRecord` 虽能生成 `ignorable:true`、可随 fork/resume 携带的记录，但官方合同限定给仓库 `packages/experimental/` 内的生产包；直接 `session.append('plugin:dsh-science/...')` 产生的未知、非 ignorable event 会被持久化校验拒绝。[官方限制](../../../../test-env/node_modules/@deepseek-ai/dsh-session/README.zh.md#L68-L78) [类型合同](../../../../test-env/node_modules/@deepseek-ai/dsh-session/lib/types/index.d.ts#L96-L121) [未知事件拒绝](../../../../test-env/node_modules/@deepseek-ai/dsh-session-persistence/lib/types/storage-contract.d.ts#L25-L38)。本次最小运行实测与该合同一致。生产方案不得依赖 declaration merging、未知事件或 `appendPluginRecord`。

## 可复用 seam

### 原生 composer 与技能按钮

**[事实] 可以安全写入，但必须从 session-scoped slot 使用注入的 `inputActions`。**点击时先调用 `captureInsertion()` 得到包含 draft revision 的 span，再调用 `insertText(text, span)`；若草稿已变化、被冻结或被提交占用，返回失败，界面提示用户重试，不覆盖原稿。[InputActions](../../../../test-env/node_modules/@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/input.d.ts#L234-L263) [草稿状态](../../../../test-env/node_modules/@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/input.d.ts#L273-L286) [slot 注入](../../../../test-env/node_modules/@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/slots.d.ts#L481-L495)

推荐按钮文案为“填入对话”，插入 `\n/sci-research …` 后仍由用户审阅并发送；只有明确标为“立即发送”的动作才调用 submit。不得操作 Lexical DOM、广播全局 window event，或读出 `state.draft` 后整段 `setDraft`，后者可能丢失引用 chip。初始化空会话可用 `requestDraftInitialization(..., {whenDraftExists:'append'})`。[初始化语义](../../../../test-env/node_modules/@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/input.d.ts#L205-L232) `/skill` 在用户输入中按空白边界识别，追加写入有效。[Skill README](../../../../test-env/node_modules/@deepseek-ai/dsh-tool-skill/README.zh.md#L56-L89)

实际紧凑入口是 `conversation.input.dock`，不是 `conversation.composer.context`；Goal 已在该 slot 中读取投影并以 CAS ref 更新。[官方 slot 树](../../../../research/dsh-repo/docs/subsystems/slots.zh.md#L140-L196) [Goal 实现](../../../../test-env/node_modules/@deepseek-ai/dsh-client-ui-goal/lib/client.js#L684-L747)。轮次后的提案、结果和交付物用 `conversation.chat.turnTail`；右栏使用静态 tab 定义加 keyed `sidebar.right.pane.tab` body，当前插件已采用这一注册方式。[现有注册](../../client-src/index.jsx#L77-L88)

### ConversationNodeDefinition、提交与 durable receipt

**[事实]** `ConversationNodeDefinition` 用 `match/start/update` 将 durable 或 transient event 归并为稳定节点，并提供只向前读取前序节点的能力。[定义](../../../../test-env/node_modules/@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/conversation.d.ts#L174-L230)。DSH Science 仅应用它折叠官方事件：工具的 `tool/call`/`tool/result`、命令生命周期、Action Card 决策；业务身份使用 callId、cardId、objectId+revision，不用标题或数组序号。它不应读取项目存储。

用户语义请求走原生 composer/user prompt；`session.prompt` 明确区分 `queue` 与 `steer`。[session API](../../../../test-env/node_modules/@deepseek-ai/dsh-api-session-controller/lib/types/client/sessions/session.d.ts#L131-L152)。确定性、非模型操作可走 `session.command(line)`；Host 的 commands 执行会写 `command/run`，结束后写 `command/done`，但结果只有成功/错误文本及可选 `sourceEventSeq`，不能承载完整项目快照。[命令 API](../../../../test-env/node_modules/@deepseek-ai/dsh-commands/lib/types/index.d.ts#L90-L142) [命令事件](../../../../test-env/node_modules/@deepseek-ai/dsh-commands/lib/types/types.d.ts#L89-L118)

需要“稍后审批精确版本”的操作优先使用 Action Cards：kind 注册 details schema、verbs、permission、reconcile 和 handler；`actionCards` 官方 projection 会折叠提案与 durable decision，Host act 还做 root/owner/permission 和 single-flight 检查。[Action Cards README](../../../../test-env/node_modules/@deepseek-ai/dsh-action-cards/README.zh.md#L38-L60)。卡片 details 只放 `objectId + expectedRevision + expectedHash + 摘要`，handler 在服务端重新解析 scope 并 CAS；不要写入大数据或秘密。即时高风险工具调用仍用 user approval，但其请求要求 open turn，不适合作为长期待办。

## project + root session 绑定

**[事实]** 当前实现从全局 `$DSH_HOME/dsh-science` 读取状态，`/plugins/dsh-science/state` 无 session 参数，并以 5 秒整包轮询更新，存在跨项目串读和陈旧覆盖风险。[全局目录](../../lib/store.js#L6-L10) [无作用域路由](../../lib/httpdata.js#L325-L341) [轮询](../../client-src/workbench/use-workbench-state.js#L4-L31)

**[推断/推荐]** Host 端唯一解析 `ProjectScope = {projectId, rootSessionId, workspaceId, branchId?}`：调用方只提供当前 `sessionId`；若该 session 的 `parentSession` 同时被 lead 的 `agentTeam.members` roster 确认，则 teammate 与 lead 共用 root；否则当前 session 自成 root。不能只沿 `parentSession` 向上追，因为普通 fork 也有父 session；官方 Agent Team 正是通过 roster 验证避免误归组。[官方成员解析](../../../../test-env/node_modules/@deepseek-ai/dsh-experimental-agent-team/lib/types/roster.js#L63-L89)

普通 fork 默认建立写时复制分支，记录 `baseProjectId/baseRevision`，不与父会话共享可变状态；只有显式 attach/merge 才合并。每个读取、变更和卡片 handler 都重新校验 `session -> scope`，拒绝客户端自报路径、projectId 或 childId。

## 低缺陷写入与恢复

建议变更信封：`{mutationId, expectedRevision, objectId, expectedObjectRevision, expectedHash, action, payload}`。服务端在同一原子事务中写入新 snapshot/revision、审计记录、幂等 receipt 和 outbox；提交后才推送。重复 `mutationId` 返回原 receipt，陈旧 revision/hash 返回结构化 conflict。通知失败不回滚已提交业务写入，由 outbox 重试，并返回 `committed:true, notification:'pending'`。

客户端只做 pending overlay；权威 frame 至少含 `projectId/rootSessionId/revision/changedKeys/operationId`。只接受更高 revision，发现缺口立即取完整 baseline。重连使用新的 generation：先建立观察流再取 snapshot，或由服务端返回一致 cursor；丢弃旧 generation 响应。断线时可展示 last-known-good，但必须标为“可能已过期”。固定 5 秒全量轮询仅保留为短期降级，并带 ETag/revision。

旧全局数据不自动分配给多个项目。迁移先生成候选与文件哈希备份，让用户选择目标 root/project；按 `schemaVersion + migrationId` 幂等写入新库，核对数量和哈希后再切换 binding，旧数据保持只读。

## 必做 spike 与测试分层

以下均为**未验证项**，通过前不得写成产品保证：

1. composer spike：含文本和引用 chip 的草稿中 capture/insert，验证 undo、chip 保留、并发 revision 失败、claimed/sending 拒绝、skill 识别且不自动发送。
2. scope spike：lead+teammate 共享；普通 fork 隔离；伪造 child/project 被拒；两个工作区并发无串读。
3. stream spike：断线重连、baseline 与 frame 乱序、revision gap、重复 mutation、发布失败后的 outbox 恢复。
4. Action Card spike：刷新后仍在、双击 single-flight、stale revision 冲突、外部完成后的 reconcile。
5. 负向事件 spike：把本次 unknown event/`appendPluginRecord` 最小复现固化为兼容性测试；升级 DSH 时重新跑，但不把禁用 API 纳入生产。

测试按层执行：纯单元测试覆盖 scope、CAS、幂等、reducer、迁移；集成测试覆盖 Remote、存储事务、outbox、Action Cards；组件测试覆盖 dock/turnTail/right-sidebar 与 `inputActions`；真实 DSH Web E2E 覆盖多 session、teammate、fork、离线、刷新和旧数据迁移；故障注入覆盖 commit 后 crash、重复/乱序 frame 和损坏文件。验收标准是：无跨项目泄漏，陈旧写入必拒绝，重复请求收敛到同一结果，重连后状态完全一致，fork 语义明确，旧数据可追溯且不丢失。
